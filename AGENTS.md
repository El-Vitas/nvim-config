# AGENTS.md

Personal Neovim 0.12 config with lazy.nvim. `~/.config/nvim` is a symlink to this folder. Caution is preferred over speed: a change that breaks the editor leaves the owner without their work tool.

## Map

| Path | What is there |
|---|---|
| `init.lua` | lazy bootstrap, leader, own modules and `lazy.setup` |
| `lua/config/` | Own modules: options, cheatsheet (`keymaps.lua`), buffer limit, binaries (`open.lua`), hidden-files state (`hidden.lua`), markdown table grid (`mdtable.lua`), markdown preview (`mdpreview.lua`) |
| `tests/` | Tests with the full editor and real keys (`tests/run.sh`) |
| `lua/plugins/` | One lazy spec per plugin or group |
| `lua/material_folders.lua` | Table generated by `../material-font`. Not edited by hand |
| `fonts/` | `MaterialFolders.ttf` and its fontconfig rule, copied from `../material-font` for the installer |
| `install.sh` | One-line installer for another machine (documented in `README.md`) |
| `docs/business-rules/` | What the editor has to do. Queried with the CLI |
| `docs/decisions.md` | Why it is built this way, with the measurements (`D-NN`) |
| `tools/rules-cli/` | CLI of the rules registry (bun) |
| `.agents/skills/` | Skills of the repo; `.claude/skills/` are links to them |

Sibling repos in `~/Dev/nvim`: `review-mode/` (review plugin, published as `El-Vitas/review-mode.nvim`; with `dev = true` lazy uses the local copy if it exists and otherwise the one from GitHub) and `material-font/` (generator of the folder icon font). If the font is regenerated, it is copied again to `fonts/`.

## Before changing anything

1. Check the rules of the area: `bun run rules:query --features --names` and `bun run rules:query --feature FEA-XXX`. A change that breaks an active rule is a bug, even if the code ends up prettier. The `business-rules` skill explains how to add or replace rules.
2. Read the decision the code cites (`D-NN` in `docs/decisions.md`). Several parts touch plugin internals (neo-tree, gitsigns, render-markdown) and the reason is there.
3. A new or changed decision is written in `docs/decisions.md` in the same change.

## Repo rules

- **Files.** Every change to a file is made with the editing tools, file by file. Never with `sed -i`, heredocs, `python -c` or redirections. The rules CLI and lazy (which rewrites `lazy-lock.json`) are the only tools that write files of the repo.
- **Language.** Commit messages, docs, `README.md` and the text the user sees inside Neovim (notifications, cheatsheet) are in English. Code comments stay in neutral Spanish, with no voseo and no regional idioms.
- **Comments.** They explain the why, in the present tense. History and measurements go in `docs/decisions.md`. Details in the `code-comments` skill.
- **Prose.** Docs, rules and commit bodies follow the `vitas-writing` skill.
- **Git.** `git-flow` skill: always git flow (branch from `develop`, PR to `develop`, `develop` → `main`), never `git add .`, commit and push only when the owner asks, no co-author trailers.
- **Subagents.** Before launching subagents, ask the owner which model and how many.
- **Performance.** `<leader>e`, `<leader>s` and switching buffers have a budget (rule "Opening the tree and switching buffers do not freeze the editor"). Nothing synchronous against git or the disk in `BufEnter` or `WinEnter` autocmds, tree renders or the statusline.
- **Timers.** One `vim.uv.new_timer()` reused per module, not `vim.defer_fn` + `stop()` (D-13).
- **Autocmds.** Always with an `augroup` and `clear = true`.

## How to verify a change

`tests/run.sh` tests what has cases that are hard to see by hand, such as the markdown preview. It runs in a temporary repo and does not touch the sessions. If something it tests is changed, run it. In addition, the minimum for any change:

```bash
# starts without errors or warnings
nvim --headless +'lua vim.defer_fn(function() print(vim.api.nvim_exec2("messages",{output=true}).output) vim.cmd("qa!") end, 2000)'
# plugin health
nvim --headless +'checkhealth vim.deprecated lazy vim.lsp' +'w! /tmp/health.txt' +qa
```

For changes to the tree, the session or startup, measure the blocking time in a large repo before and after, with `XDG_STATE_HOME` pointing to a temporary folder so the real sessions are not overwritten. The reference figures are in `docs/decisions.md`.

review-mode has its own suite (`tests/`, busted via plenary) and its own docs (`docs/decisions.md`, `docs/performance.md`).
